# 商品目录闭环 Implementation Plan

> **For agentic workers:** 使用 subagent-driven-development 执行后端实现及独立规格/质量审查。UI 与云环境集成由主 agent 负责。步骤完成后更新勾选，不能用单测替代实调。

**Goal:** 商家可维护分类、商品、SKU、图片、库存和上下架，小程序可浏览标准商品、查看规格与只读材料目录。

**Architecture:** 延续 business-api 模块化单体、薄 Handler、领域 Service、参数化 DAO、同连接 UnitOfWork。继续 CloudBase MySQL，不迁库；已有 20 表不重建。

**Tech Stack:** TypeScript / Node.js 事件云函数、mysql2、Vue 3/Vite、微信原生小程序 Skyline、CloudBase 云存储。

## 边界与验收

1. 管理员创建分类时，前后端校验名称、类型、排序和启用状态；已有商品不能修改分类类型。
2. 商品保存完整公共资料；STANDARD 的 spec_schema 定义维度与选项，已有 SKU 不得因修改规格定义失效。
3. SKU 保存全量可编辑字段，库存通过 adjustInventory 单独调整；STANDARD 规格规范化后 SHA-256，锁父商品防止重复组合。
4. 调整库存写唯一事件流水；同 operation_key 网络重试不得重复调整；总库存不得低于预占。
5. SKU 下架/删除必须先预览并确认；存在预占禁止操作。AVAILABLE 券按原积分退分，账户/流水/券/SKU 同事务更新；摘要变化须重新预览。
6. 分类/商品停用前检查子 SKU 预占；删除须先处理子记录；不清除历史快照与素材。
7. 标品列表分页、详情按 spec_schema 渲染选择，切换规格对应唯一 SKU、价格和库存。DIY 材料按接口返回，不能购买的置灰。
8. 只实现商品目录阶段：不创建购物车/订单，不伪装购买成功，后续购买入口须清晰说明尚未开放。
9. 图片使用真实上传的 cloud:// 文件标识，展示时用 SDK 解析，不拼 URL。生成素材只能作为有标识的开发样例，不能当真实商家商品。
10. 新增和保存请求期间禁用、错误保留输入、显式确认破坏性操作；测试错误信息、键盘焦点与窄屏布局。
